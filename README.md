# physical-ai-corp-project

> **AI 협동로봇 기반 공장&창고 안전관리 시스템**  
> 청년 피지컬AI 2기 · 10팀 포텐 기업 과제 주차별 기록 저장소

[웹에서 보기 (목차)](https://myeongsu-dev.github.io/physical-ai-corp-project/)

MechDog 4대가 공장·창고 통로를 교대로 순찰하며 막힌 통로·바닥 물건·안전모 미착용·화재를 찾아 알리고, 화재가 확정되면 갈림길에서 막힌 길과 불을 피해 비상구로 안내하는 프로젝트를 정리해 둡니다.

## 프로젝트 정보

| 항목 | 내용 |
|---|---|
| 팀 | 10팀 포텐 (박명수 · 이예은 · 채웅 · 김건주) |
| 멘토 | 류찬무 |
| 기간 | 2026. 11. 04 ~ 12. 21 |
| 교구 | MechDog 4대 · 센서·비전 확장 모듈 · 라즈베리 파이 5 4대 |

## 주차별 기록

### 1주차 · 11. 09 ~ 11. 13 (`week01/`, 1회차 멘토링)

| 번호 | 문서 | 내용 |
|---|---|---|
| 01 | 기획 배경 | 무엇을, 왜 만드는지 · 주제가 정해진 과정 · 범위 조정 · 출처 |
| 02 | 기능 정의서 | 우선순위 기준(MoSCoW), 기능 목록과 상세, 이번에 하지 않는 기능 |
| 03 | 미션맵 | 시연 무대의 크기와 배치, 순찰 경로, 바닥 마커, 동선 규칙, 대피 안내 자리 |

### 2주차 · 11. 16 ~ 11. 20 (`week02/`, 2회차 멘토링)

| 번호 | 문서 | 내용 |
|---|---|---|
| 01 | 시스템 아키텍처 | 장치 역할, 판단 위치, 통신, 주요 흐름, 로봇 상태, 소프트웨어 구성 |
| 02 | 재료 목록 | 11/16 주문 신청 품목, 보유분, 3D 출력 품목, 수령 때 확인할 것 |
| 03 | 개발 계획 | 개발 방식(MoSCoW + 타임박스), 역할, 등급별 개발 순서, 일정 |
| 04 | 로봇 하드웨어 | 부품을 다는 자리와 배선, 무게 배치, 3D 장착 모델 |
| 05 | AI 모델 | 안전모 · 불꽃 모델 구성, 데이터, 라벨링, 학습과 변환, 평가 |
| 06 | 기술 검증 | 만들기 전에 먼저 확인할 것과 안 될 때의 대안 |
| 07 | 시연 시나리오 | 발표 시연의 장면 순서, 시뮬레이션, 소품 |

### 3주차 · 11. 23 ~ 11. 27 (`week03/`)

| 번호 | 문서 | 내용 |
|---|---|---|
| 01 | MechDog 구현 | 보드 프로그램, 선 따라가기와 비전 모듈 펌웨어, Pi 5 연결, 시험 도구, 실기 확인 결과 |
| 02 | Pi 5 구현 | 서버 명령을 보드 명령으로, 보드 답 확인, 안전 정지, 점검 도구, 시험 결과 |
| 03 | 서버 구현 | 관제 서버 구조, 파일별 기능, 과열 교차 확인, 진행, 실행 방법 |
| 04 | 대시보드 구현 | 기본 · 관리자 화면, 만든 방식, 정한 것, 연결 끊김 시험 |
| 05 | 1차 통합 시연 | 서버 명령 → Pi 5 → MechDog 선 따라 걷기, 통합 시나리오 결과, 시연 중 찾아 고친 것 |

## 폴더 구성

```text
physical-ai-corp-project/
├── index.html                  # 주차 선택 페이지 (웹 포털)
├── serve.cmd                   # Windows에서 더블클릭: 로컬 서버를 켜고 index.html을 연다 (3D 뷰어는 웹 서버에서만 뜸)
├── assets/                     # 모든 문서가 같이 쓰는 스타일·스크립트 (목록은 assets/README.md)
│   ├── doc.css · doc.js        # 문서 공통 컴포넌트 (표 · 배지 · 요점 상자 · 상단 바 등)
│   ├── diagram.css · diagram.js # 그림 도형 재료, Mermaid 불러오기
│   ├── index.css               # 목차 페이지
│   ├── components.html         # 컴포넌트 견본
│   ├── diagrams.html           # 그림 형태별 견본
│   ├── template.html           # 새 문서 틀
│   ├── 3d/                     # 3D 장착 모델 위젯 (viewer.js) · MechDog GLB(CAD에서 만듦) · 출력 파일(print/) · 공식 부품 GLB
│   └── sim/                    # 미션맵 시뮬레이션 위젯 (missionmap.js)
├── week01/                     # 1주차 (11/09~11/13) 산출물
│   ├── index.html              # 1주차 문서 목차
│   ├── 01_기획배경.html
│   ├── 02_기능정의서.html
│   ├── 03_미션맵.html
│   └── (01_주제선택_배경 · 03_미션맵_시연구성안 · 04_재료_목록)  # 예전 주소 연결 페이지
├── week02/                     # 2주차 (11/16~11/20) 산출물
│   ├── index.html              # 2주차 문서 목차
│   ├── 01_시스템_아키텍처.html
│   ├── 02_재료_목록.html
│   ├── 03_개발계획.html
│   ├── 04_로봇하드웨어.html
│   ├── 05_AI모델.html
│   ├── 06_기술검증.html
│   └── 07_시연시나리오.html
├── week03/                     # 3주차 (11/23~11/27) 산출물
│   ├── index.html              # 3주차 문서 목차
│   ├── 01_MechDog구현.html
│   ├── 02_Pi5구현.html
│   ├── 03_서버구현.html
│   ├── 04_대시보드구현.html
│   └── 05_1차통합시연.html
```

산출물은 만든 주의 `weekNN/` 폴더에 두고, 내용이 바뀌면 그 자리에서 계속 고칩니다. 주차는 월~금 기준이며 1주차는 11/09~11/13입니다. 문서 이름은 `번호_제목.html`이고, 번호는 그 주 안에서 이어 붙입니다.

문서는 본문만 담고 생김새는 `assets/`의 공통 컴포넌트에서 가져옵니다. 새 문서는 `assets/template.html`을 주차 폴더에 복사해 시작합니다. 회의 폴더(`archive/…/materials/`)의 원본은 회의 때 기록으로 남기고, 공개한 뒤에는 이 폴더의 문서만 고칩니다.
