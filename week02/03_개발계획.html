개발 계획

포텐 (10팀) · 개발 방식, 역할, 개발 순서, 12/7 제출까지의 일정 (2026. 11. 19 기준)

근거: 11/12 팀 회의(개발 방법론), 11/18 2회차 멘토링, 11/19 팀 회의

기본 동작만 먼저 만들어 11/23에 한 번 묶고, 그 위에 Must → Should → Could 순서로 기능을 더한다. 기능 구현은 11/29에 끊고, 남은 기간은 E2E 테스트와 결과보고서에 쓴다.

1. 개발 방식

MoSCoW 우선순위 + 주 단위 타임박스로 진행한다. 등급 기준과 기능별 등급은 기능 정의서 2·3절.

규칙내용
마감 고정12/7 제출과 12/10 발표는 옮기지 않는다. 시간이 모자라면 기능을 아래 등급부터 뺀다 (Could → Should)
주 단위 타임박스한 주가 한 칸이다. 매주 남은 시간을 보고 기능의 등급을 다시 정한다
미리 시험될지 모르는 것은 만들기 전에 되는지만 먼저 확인한다 (기술 검증)

2. 역할

주요 파트는 한 사람이 하나씩, AI 학습은 두 사람이 모델 하나씩 맡는다.

주요 파트담당하는 일다른 파트와 맞출 것
MechDog박명수보드 프로그램, USB 시리얼, 선 · 색 마커 · 초음파 튜닝, 장착(3D 출력), 미션맵 주행아키텍처 4-1 보드 명령
라즈베리 파이 5김건주보드 · 카메라 · 온도 센서 연결, 모델 추론 실행, 화재 의심 판정, 사진, 서버 보고아키텍처 4-1 보드 명령 · 4-2 이벤트 형식
관제 서버채웅MQTT, 위치 계산, 교차 확인, 교대 · 출동 · 대피 · 우선권, 가짜 로봇아키텍처 4-2 · 4-3 전체
관제 대시보드이예은지도 화면, 사진 팝업 · 경보음, 모바일 알림 시안아키텍처 4-3 화면 데이터
AI 학습담당하는 일
안전모 모델채웅 · 이예은데이터 모으기 · 라벨링 · 학습 · Pi 5용 변환 (AI 모델)
불꽃 모델박명수 · 김건주데이터 모으기 · 라벨링 · 학습 · Pi 5용 변환, 온도 판정과 맞추기 (AI 모델)
  • 함께 하는 일: 미션맵 제작(하루 날을 잡아 넷이 함께), 발표자료, 결과보고서 · 요약본, 최종 발표
  • 일하는 방식: 자기 파트만 하지 않는다. 막히면 바로 팀에 알리고, 먼저 끝난 사람이 돕는다. 대시보드는 시안이 나올 때마다 팀 피드백을 받는다.
  • 코드: 팀 GitHub 저장소(physical-ai-safety-patrol)에서 파트별 폴더로 나눠 작업한다. 기능 브랜치에서 만들어 dev로 PR을 올리고, 시연할 수 있는 안정판만 main에 둔다. 파트마다 check.sh 자동 검사가 돈다.

3. 개발 순서

기능을 다 만든 뒤 묶으면 서로 안 맞는 곳이 한꺼번에 터진다. 그래서 모든 기능의 바탕인 기본 동작을 먼저 묶고, 통합된 상태에서 등급 순서로 기능을 더한다.

단계만드는 것기능
기본 동작MechDog 걷기 · 멈추기, Pi ↔ 보드 명령, 서버 ↔ 대시보드 연결 (가짜 로봇으로)—
Must검정 선 주행, 색 띠 · 갈림길 색 선 읽기, 초음파 정지와 사진 보고, 관제 지도F-01 · F-02 · F-03 · F-08
Should온도 센서와 불꽃 · 안전모 모델 판정, 바닥 물건, 재점검, 교차 확인, 충전 교대, 대피 안내F-04 · F-05 · F-06 · F-09 · F-10 · F-11 · F-12
Could보행자 구분, 로봇 동선 조율F-07 · F-13

AI 학습은 오래 걸리므로 학습을 돌려 두고 기능 구현을 함께 진행한다.
