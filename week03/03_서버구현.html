서버 구현

담당 채웅 · 노트북에서 도는 관제 서버 server/ · 2026. 11. 26 기준

관제 서버는 MechDog 여러 대를 엮는 판단을 맡는다. 로봇 상태를 모아 순찰 역할(A · B)을 주고, 이벤트를 판단 · 기록하고, 로봇에 명령을 보내고, 대시보드에 실시간 데이터와 사진을 준다. 로봇 한 대 안의 판단은 각 Pi가 한다.

1. 구조

  • 입력: potent/{로봇}/state · potent/{로봇}/event, 사진 업로드, 대시보드의 경보 해제
  • 출력: potent/{로봇}/cmd · potent/mode, 대시보드 WebSocket
  • 형식: docs/protocol.md 2 · 3절과 common/protocol.py

2. 파일별 기능

파일하는 일상태
api.py서버 입구(FastAPI). MQTT를 받아 fleet · events에 반영하고 /ws로 보냄. 사진 업로드, 경보 해제, 순찰 시작, 모드 변경, 연결 끊김 · 다시 붙음 알림완료
fleet.py로봇별 마지막 상태. 5초 안에 state가 온 로봇만 연결로 봄. 순찰 역할 A · B 부여, 서버를 다시 켜도 역할 복구상태 전환 남음
events.py이벤트 · 사진 SQLite 기록, 과열 교차 확인완료
map_config.py마커 1~15 위치, A · B 순찰 순서, 갈림길 동작, 배터리 복귀 규칙합류점 우선권 대기
fake_robots.py가짜 로봇 4대(A~D). MQTT로 상태 · 이벤트를 흉내 내 로봇 없이 개발완료
dispatch.py충전 교대, 출동 로봇 고르기, 대피 배정미구현
mosquitto.conf같은 Wi-Fi의 Pi 접속을 받는 브로커 설정완료
check.shCI 검사. 파일별 셀프 체크를 차례로완료
과열 교차 확인: 로봇 X가 마커 M에서 과열을 보고하면 X는 기다리고 다른 로봇 Y가 M으로 갑니다. 두 대 모두 50℃를 넘고 불꽃이 한 번이라도 보이면 화재로 확정하고 대피 모드로 바꿉니다. 90초 안에 확정되지 않으면 풀고 둘 다 순찰을 이어 갑니다.

4. 실행

노트북에 Mosquitto(포트 1883)가 있어야 합니다.

할 일명령
설치pip install -r server/requirements.txt
가짜 로봇 4대python -m server.fake_robots
서버python -m server.api → http://localhost:8000
셀프 체크bash server/check.sh (CI와 같음)

Pi는 .env의 MQTT_HOST에 노트북 주소를 적습니다. 대시보드는 ws://서버:8000/ws에 붙어 상태와 이벤트를 받습니다.

5. 남은 일

할 일내용
충전 교대dispatch.py. 배터리 20% 미만(임시)이면 대기 로봇에 구간을 넘김
출동 로봇경로 거리 기준으로 고르기. 지금은 events.py에서 임시로 고름
상태 전환fleet.py: 대기 · 순찰 · 막힘 정지 · 과열 확인 · 출동 · 대피 안내 · 복귀
대시보드 요청지난 경보 목록(GET /events), 관리자 화면 잠금
서버가 정할 값서버가 통제할 항목(파라미터)과 스펙을 정리하고 다른 파트와 경계를 정함 (11. 24 멘토링)
다른 파트와 정할 것
팀 전체A · B가 도크 길이나 갈림길에서 동시에 만날 때 누가 먼저 갈지
Pi 5진행 방향(N · E · S · W)을 state에 실을지, 갈림길 판단을 서버와 Pi 중 어디서 할지
대시보드대피 mode 메시지에 화재 위치("fire": {"segment": [5, 6], "zones": ["A1", "B1"]})와 갈림길 화살표("guides": [{"marker", "dir", "exit", "path"}])를 실을지. 대시보드가 낸 제안 모양
